# Core.Model

The domain model for the MMA management sim. Pure .NET 8, zero external
dependencies, and completely UI-independent — this is the "world" layer that
`Core.Sim` (fight engine + world tick) will read and mutate, and that
`Persistence` will serialise.

## Conventions

- **Ratings are 0–100.** The `Rating` struct clamps on construction, so an
  out-of-range value can't exist anywhere in the model. Implicit int
  conversions keep assignment and sim math clean.
- **Ids are strongly typed** (`FighterId`, `PromotionId`, …). You can't mix
  them up by accident, and they're valid dictionary keys out of the box.
  `Value == 0` means "unset".
- **Entities reference each other by id, never by object reference.** This
  keeps the graph acyclic and trivial to serialise. `World` is the one place
  ids get resolved to objects.
- **Mutable classes vs. value types.** Anything the sim changes over time
  (`Fighter`, `Promotion`, `Event`, `Title`, `World`) is a mutable `sealed
  class`. Anything that's just a value (`Rating`, `Money`, the ids, records)
  is an immutable `struct`/`record`.
- **Derived data isn't stored twice.** A promotion's roster is derived from
  contracts (`World.RosterOf`); a title's holder lives on the `Title`, not
  also on the `Division`. `FightRecord` is the one intentional cache and is
  updated by the sim when a bout completes.

## Current / Potential ability

Each fighter carries a hidden `PotentialAbility` ceiling. The growth model
(coming in `Core.Sim`) raises individual skills toward, but never past, an
overall ability derived from that cap — the Football-Manager CA/PA idea. The
weighting of which skills count how much toward "overall" lives in the sim
layer, not here, so it can be tuned without touching the model.

## Saves

The whole `World` graph serialises as the save file. Two things to wire up in
the `Persistence` project:

1. Call `World.SyncIdCounters()` immediately after loading — the id counters
   are private and don't persist, so this resets them above existing ids.
2. Respect `SaveVersion` for migrations as the model evolves.

`FightOutcome.PlayByPlay` can be dropped on save to keep files small; with the
deterministic `RngSeed` it can be regenerated by re-simulating the bout.

## File map

| File | Contents |
|------|----------|
| `Ids.cs` | Strongly-typed entity ids |
| `Rating.cs` | The 0–100 clamped `Rating` value type |
| `Money.cs` | `decimal`-backed currency value type |
| `Enums.cs` | WeightClass, Stance, PrimaryStyle, Region, FightMethod, … |
| `WeightClasses.cs` | Weight-class limit lookup |
| `Attributes.cs` | Striking/Grappling/Physical/Mental ratings + Tendencies |
| `Fighter.cs` | `Fighter` + `FightRecord`, `Contract`, `Injury` |
| `Promotion.cs` | `Promotion` + `Division`, `Title`, `TitleReign` |
| `Events.cs` | `Event`, `Fight`, `FightOutcome`, `FightStatline`, `EventFinancials` |
| `World.cs` | Aggregate root: id generation, lookups, save root |
